Torrent Activity Scheduler, phase 2: the pure policy and planning layer. No behaviour changes ship with this — nothing is wired to a provider, no sweep runs, no torrent is touched. It is the decision layer the later phases will drive, kept side-effect free so Observe Only and enforcement can run the SAME function, which is the only way a preview is trustworthy. Policy resolution walks torrent, RSS rule, category, library, engine, global, field by field, so an override is a patch rather than a replacement. Three states are distinguished deliberately: absent inherits, null means explicitly unlimited and STOPS inheritance, a number is a cap — without that distinction a library cannot lift a global limit, because 'no limit here' and 'ask my parent' would be the same token. Classification separates what a torrent OCCUPIES from what the engine reports, because engine state does not answer the question. rTorrent's normalizer maps everything running and incomplete to DOWNLOADING, so a torrent waiting for a slot is indistinguishable from one transferring; that case is now classified with confidence 'inferred' and a reason code saying so, rather than asserted. Every paused torrent likewise reports PAUSED whether a person, the scheduler, or the engine paused it, so scheduler-owned state decides, and a pause nobody here claims is never resumed. Capabilities are graded native / approximated / unsupported rather than boolean, because qBittorrent's force-start sets a real flag while rTorrent's provider says outright it has no force flag and uses priority 3 — a boolean would let the UI promise something one engine cannot deliver. Seed targets return met / not_met / UNKNOWN: nothing in this repository tracks seed duration today, so a time-based target is unknowable on both engines, and unknown is reported rather than read as zero, which would seed forever, or as met, which would stop early. The planner enforces download, seed and total-active limits independently, never resumes a user-paused or externally-paused torrent, never pauses a protected one, leaves parked torrents to the existing TorrentParkingService rather than fighting it for control, bounds actions per sweep, and refuses to plan at all for an engine that cannot pause. Ordering is deterministic with incumbency as the first tie-break, so two equally-ranked torrents do not swap places every sweep. 36 unit tests.
