Torrent Activity Scheduler, phase 10: hardening and documentation. The security review was an audit of the shipped code rather than a description of intentions, and it found two real defects. The first was an unbounded query: the preview asked for every Media Intake job an engine had ever recorded, on every sweep, to answer a question about the couple of hundred torrents currently loaded — fine on a new install and ruinous on a two-year-old one. It is now bounded by the hashes actually in the snapshot, at the cost of one extra round trip, which buys a bound that does not decay. The second was a credential leak. A provider error message was going straight into a domain event payload, and a scheduler event reaches the automation engine and from there a webhook to somebody else's server — a path the operator cannot un-send. Provider errors are written by libraries with no idea the string will travel, and a failed call can embed a base URL, an SCGI target or a tracker passkey. Messages entering an event are now redacted: URL credentials, secret-looking query parameters, whole URLs and long hex runs, truncated to 300 characters. Deliberately aggressive, because a message that loses a hostname is mildly less useful while one carrying a passkey to a third party is a leak; the application log keeps the full text for whoever is debugging. Two documents accompany it. TORRENT_SCHEDULER_SECURITY.md states what the scheduler can do, what stops it doing more, and — in its own section — six things that are NOT protected, because a security document listing only what is handled is misleading; the first of those is that none of this has run against a live engine. TORRENT_SCHEDULER.md is the operator guide, including a table of what is enforced today and what is refused as unenforceable, and a troubleshooting section for the four questions the design guarantees will be asked. The architecture change log records the work with its verification, and says plainly that live-engine verification is outstanding. 7 unit tests for the redaction.
