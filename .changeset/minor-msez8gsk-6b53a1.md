Scheduling policies can be created, and enforcement can be switched on, from the app. Phase 5 built managed scheduling but left it reachable only by curl: there was no way to create the limits it enforces, so the feature existed without being usable. Policies now have full CRUD with typed fields and a new torrent_scheduler.manage_policies permission, which is added now rather than earlier because it finally guards something real. Only the three concurrency limits are offered. Bandwidth and seeding columns exist in the schema for the phases that will enforce them, and showing those fields today would let an operator configure a rate limit that silently does nothing to their queue — the same failure the cleanup policy builder was rebuilt to avoid, wearing a different costume. An empty box means unlimited and is written as an explicit null rather than omitted, because that is what allows a narrower policy to LIFT a broader one's cap rather than only tighten it; an untouched field is omitted, so editing a name cannot silently make every limit unlimited. Zero is rejected: it reads like a way to stop the queue but is indistinguishable from a typo and would pause every torrent on the engine, and pausing is the honest verb for that. A global policy naming a scope id is refused rather than quietly normalised, since 'global, but only for this library' is a contradiction the resolver would ignore while the operator believed it honoured. Activation is a consent dialog, not a menu option: choosing managed opens a preview of the CURRENT queue showing how many torrents would be paused and resumed, blockers that disable the button outright, and warnings that do not — including that junk-queue parking may also be pausing torrents on the same engine, and that with no policies enabling enforcement would change nothing at all. Leaving managed mode asks what to do with the torrents the scheduler is holding paused, defaulting to leaving them paused and saying why. The permanent Observe Only banner now hides once any engine is enforcing, because leaving it up would tell an operator nothing is being applied while it is. Full en-US and es-PR.
