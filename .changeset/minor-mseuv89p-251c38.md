The Observe Only page, completing scheduler phase 3. Downloads gains an Activity Scheduler view that answers the two questions the feature exists for: why is this torrent waiting, and what would change if enforcement were switched on. The proposed-change count is the headline number because it IS the gap between the engine's queue and the operator's policy, and it is what decides whether enabling enforcement later would be safe or disruptive. A torrent's queue reason is a localized sentence rather than a code — 'waiting for a download slot (limit 3)', 'you paused this, the scheduler never undoes that', 'parked, no seeders, handled by junk-queue parking' — and proposed changes sort to the top because they are what the operator came to see. Engine limitations are shown rather than hidden: a queue view that quietly omitted 'this engine does not report which torrents are queued' would let an operator trust an inferred answer as a measured one, so rTorrent's inferred queue state, its approximated force-start, and the absence of seed-duration data on both engines all appear as plain sentences. The Observe Only notice is permanent and undismissable, because the entire value of the page depends on knowing nothing is being applied. Managed mode is listed in the selector but refused by the server with an explanation, so the road map is visible without pretending the capability exists. Full en-US and es-PR strings including every queue reason, limitation and priority reason.
