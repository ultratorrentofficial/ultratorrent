Torrent Activity Scheduler, phase 5: managed scheduling, reachable only through a guarded activation flow. Building this surfaced a correctness bug that would have made enforcement one-way. Every engine reports a paused torrent as simply paused — a person's pause, the scheduler's and the engine's own are indistinguishable from provider state — so a torrent the scheduler paused would classify as someone else's on the next sweep and never be resumed. It could take a slot away and never give it back. A new TorrentSchedulerState table records which torrents the scheduler itself is holding paused, written only AFTER the pause is verified, because a row claiming we paused something we failed to pause would let a later sweep resume a torrent a person had stopped. The table is empty on creation, so no existing paused torrent gains a scheduler attribution and nothing already paused becomes eligible for automatic resume. Enforcement is not reachable by setting the mode. Enabling it means UltraTorrent starts pausing torrents in someone's queue, so it goes through activation: the engine must actually be able to pause and resume, a preview is generated from the CURRENT queue, conflicts are reported, and the operator confirms that specific outcome. Confirmation is mandatory and a request without it is refused with the numbers it would have produced, so enforcement can only be reached by asking twice. Three warnings are worth naming: rTorrent infers its queue state and approximates force start; the existing TorrentParkingService may also be pausing torrents on the same engine, which is a conflict to disclose BEFORE a second pauser starts rather than after; and an install with no policies would see activation do nothing at all, because every limit is unlimited. The native-settings snapshot records honestly that nothing could be captured, since neither shipped engine exposes its queue settings through the provider interface — storing an empty object would imply a backup that does not exist. Deactivation returns to native and LEAVES scheduler-paused torrents paused unless the operator asks for them back, because blanket-resuming would start downloads nobody chose to start on an engine whose own limits are about to take over again; the count is reported so the choice is informed, and the resume is best-effort per torrent. 28 unit tests across activation and reconciliation.
