A post-import intake failure now says what went wrong. Three jobs on the live host failed with the same message — 'Fetch metadata: Illegal intake transition imported → quarantined' — which describes the state machine and nothing an operator can act on. Two faults combined. The metadata stage forms a legitimate quarantine opinion (the file was placed but no library item exists for it, and no retry fixes that), but imported → quarantined was not a legal edge; and when the machine refused, the pipeline recorded the REFUSAL as the failure and threw away the stage's reason. The edge is now legal, added SECOND so nextState still advances to metadata_ready rather than diverting every import into quarantine, and only for that state — no other post-import stage quarantines, so the table's principle that a stage which cannot form the opinion must not claim it still holds, with a test pinning that metadata_ready, artwork_ready and subtitle_ready stay closed. The pipeline also now carries the reason through when a quarantine is refused for any other reason, so the diagnosis can never be replaced by the machine's complaint again. Underneath, nothing was actually wrong with those three films: intake's own [dupN] move-aside had renamed the file after recording importedPath, so 'Evolution (2026) - 1080p.mp4' was on disk as '... - 1080p [dup2].mp4' and the item existed the whole time — the lookup was an equality test on the exact path and could not see it. It now falls back to matching the directory plus filename STEM, which finds a [dupN] rename or a changed extension, and deliberately not the bare directory, since a season folder holds many episodes.
