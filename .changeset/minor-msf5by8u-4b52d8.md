Torrent Activity Scheduler, phase 9: domain events and automation. Four events, each with a real producer, published on the existing DomainEventBus rather than a second mechanism — so they are catalogued, validated and idempotent for free, and the automation bridge picks them up without knowing the scheduler exists. The discipline the phase is really about is not emitting polling noise. The sweep runs every minute and reconciles the same state each time, so an event per tick would be noise an operator learns to ignore, which is worse than no event at all. Health is therefore published only when it DIFFERS from the previously stored value, which required reading the old state before overwriting it; a test asserts that a healthy engine sweeping repeatedly says nothing. The two facts that genuinely repeat — a seed that met its target, and an action that keeps failing — carry dedupe windows in the event catalogue, an hour and fifteen minutes respectively, because the sweep re-derives them for as long as the condition holds. A mode change gets no window at all: it is an operator's discrete act, and deduping two changes in a minute would hide the second. Four automation triggers and four actions follow. The actions are instructions rather than verbs — exclude, protect from pausing, protect from stopping, clear — because pause and resume already exist as automation actions and mean do this now, while these mean and keep meaning it, which is the only thing a rule can usefully say that the existing actions cannot. Clearing revokes each kind explicitly rather than through a bulk call, so a rule cannot remove an instruction its author did not know about, and an action that cannot identify its torrent throws rather than guessing, because applying an instruction to the wrong torrent is worse than not running. Fixing the specs surfaced a mis-wiring worth recording: schedulerOverrides sits between the subtitle actions and audit in the engine constructor, so appending the new stub to the end of four test harnesses silently shifted audit into its slot while the tests still passed. They are now inserted in position. 9 unit tests.
