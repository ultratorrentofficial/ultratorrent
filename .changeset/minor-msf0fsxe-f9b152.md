Torrent Activity Scheduler, phase 6: managed seeding — the enforceable half, with the rest refused visibly. A completed torrent that has met its seeding target now stops, and that is evaluated before the slot maths because it is a different question from 'is there room': a torrent that has finished its obligation should stop even when the engine is idle. Three refusals are the substance of the phase. A target that cannot be EVALUATED never stops anything: neither shipped engine reports how long a torrent has been seeding, so a time-based target is unknowable, and the planner reports that as a limitation rather than guessing — stopping early would cut seeding short and treating it as unmet would seed forever. The two post-target actions that delete data are not performed at all: taking a payload away has to pass Media Intake's ownership and path-safety checks, and a queue planner is the wrong place to acquire that authority, so the decision says the target was reached and leaves the removal to the operator. And a policy that would stop seeding waits for the import to be real first, because the usual reason to seed past completion is that the library copy is not yet safe; the scheduler reads media_intake_jobs to answer that, and answers 'not yet' when it cannot tell rather than assuming success. The policy editor gains a seeding section offering only what can be enforced — ratio, manual and unlimited, with pause, stop or leave-active — and the wait-for-import switch defaults ON for the same reason. Time-based modes and the removal actions are absent from both the API and the UI rather than present and broken, because a policy that sits in the database looking configured while doing nothing is worse than one that was never offered. 13 unit tests covering each refusal.
